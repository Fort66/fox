# Язык программирования Fox

Fox — процедурный язык программирования с лексикой в духе Visual FoxPro,
который компилируется в нативные бинарники через транспиляцию в C.
Проект включает собственный компилятор: лексер, парсер, статический
чекер типов и C-кодогенератор, написанные с нуля на C.

## Концепция

- **Нативная компиляция без собственного бэкенда.** Конвейер:
  `.fox` → C-файл → системный `gcc` → исполняемый файл. Это даёт
  переносимость, отладку по сгенерированному C и тривиальное подключение
  C-библиотек в будущем.

- **Синтаксис в духе VFP.** Блоки закрываются ключевыми словами
  (`endif`, `endwhile`, `endfor`, `endcase`, `endfunc`), а не отступами
  и не фигурными скобками. Ключевые слова регистронезависимы
  (`IF`, `if`, `If` равнозначны), имена переменных и функций — регистрозависимы.

- **Статическая типизация с локальным выводом.** Тип переменной
  выводится из инициализатора в `local` и фиксируется навсегда.
  Все проверки типов выполняются на этапе компиляции; в рантайме
  проверок типов нет.

- **Жёсткая типовая дисциплина.** Неявных приведений нет вообще:
  смешать `number` и `string` в одной операции — ошибка компиляции.

- **Нуля нет по уставу языка.** Класс ошибок «null pointer» исключён
  дизайном (в перспективе — типы Option/Result).

- **Минимальный рантайм в сгенерированном C.** Строки и списки
  обслуживаются небольшими собственными функциями (`fox_concat`,
  `fox_*_list_of` и т.д.), которые компилятор вставляет в каждый
  сгенерированный файл. До подключения сборщика мусора память
  строк и списков не освобождается — осознанное временное ограничение.


Устав языка Fox

1. Красота VFP = лексические обязательства (что уже есть и не предаётся):

    Блоки закрываются словами-терминаторами: if/endif, do case/endcase, while/endwhile, for/endfor, func/endfunc. Код читается как английский текст, без фигурных скобок и без тревожности отступов.

    Ключевые слова — английские слова, регистронезависимы (IF, if, If равнозначны); имена переменных и функций — регистрозависимы (это осознанный гибрид: читаемость VFP без её случайных коллизий имён).

    Встроенные функции с именами VFP: LEN, UPPER, LOWER, TRIM, SUBSTR, STR, VAL, COUNT — есть; IIF (vfp-ский «тернарник») — добавим, когда понадобится.

    Индексация с 1: и SUBSTR, и будущие индексы списков — как массивы VFP, а не как Python.

    FOR EACH x IN collection ENDFOR — родная конструкция VFP.

2. Гибкость Python = обязательства по возможностям (к которым идём):

    Вывод типов: не писать типы там, где компилятор сам понимает (есть для переменных; типы обязательны только на границах функций — это плата за понятные ошибки).

    Функции в выражениях, вложенные вызовы (есть); функции как значения, замыкания, map-подобные встроенные — следующий большой этап после коллекций.

    Коллекции-литералы [1, 2, 3] (есть); срезы — сначала функцией SLICE(a, from, count), синтаксис a[1:3] позже, если приживётся.

    Богатая стандартная библиотека послойно: строки → списки → словари → файлы → время/ОС.

    Быстрый цикл обратной связи: компиляция за миллисекунды, читаемый сгенерированный C; REPL — в планах.

VFP для нас — донор семантики, а не спецификация
Мы не «возрождаем FoxPro», мы берём у него несколько действительно сильных решений и пересаживаем их на современную базу. Критерий входа любой фичи из любого языка (VFP, Python, Rust — неважно) — три вопроса:

    Она совместима с нашим уставом (статическая типизация, нет null, клон при присваивании, нативный код)?
    Она всё ещё лучшее решение сегодня, или есть современное лучше?
    Она окупает свою сложность?

Происхождение не аргумент ни за, ни против. Аргумент — только заслуги.

## Текущий статус

### Реализовано

- Типы: `number` (в C — `double`), `string`, списки `number` и списки
  `string`. Булевских значений нет: `true`/`false` — это `1.0`/`0.0`,
  результаты сравнений и логики тоже `number`.

- Переменные: объявление `local x = <выражение>`, присваивание `x = ...`,
  сокращённые операторы `+= -= *= /= %= //=`.

- Арифметика: `+ - * /`, целочисленное деление `//`, остаток `%`,
  унарный минус, скобки.

- Сравнения: `== != > >= < <=` (для строк — через `strcmp`).

- Логика: `and`, `or`, `not`.

- Строки: конкатенация через `+`; встроенные функции `len`, `upper`,
  `lower`, `trim`, `substr`, `str`, `val`.

- Списки: литералы `[1, 2, 3]`, `["a", "b"]`, пустой `[]`;
  `count(список)`; глубокая копия при присваивании (`local b = a`
  не создаёт алиас).

- Управление: `if / elif / else / endif`, `do case / case / otherwise /
  endcase`, `while / endwhile`, `for i = a to b / endfor`.

- Функции: `func имя(тип параметр, ...) ... endfunc`, `return`,
  процедурные функции без `return`; параметры типов `number`/`string`;
  перегрузка встроенных по типам (`count` для обоих видов списков).

- Вывод: `print <выражение>`.

- Комментарии: `*` в начале строки до конца строки.

- Инструменты: CLI-компилятор `foxc`, регрессионный прогон
  `run_tests.sh` с эталонами вывода, юнит-тест лексера
  `tests/test_lexer.c` (все ключевые слова в двух регистрах плюс
  «похожие» идентификаторы).

### Не реализовано (осознанно отложено)

- Индексация списков `a[0]` и присваивание элементу (шаг 4b очереди).
- `append`, цикл `for each` (шаг 4c очереди).

- Списки как параметры и возвращаемые значения функций; вложенные списки.

- Печать и сравнение списков напрямую (компилятор даёт внятную ошибку).

- Рекурсия и объявление функции после места вызова.

- Ввод с клавиатуры, работа с файлами, модули/импорты.

- Классы, словари, строковые срезы, сборщик мусора, FFI.

## Быстрый старт

Требования: Linux/macOS — gcc или clang плюс make; Windows — см. раздел ниже (w64devkit / MinGW / MSVC)».

1. Собрать компилятор:

   ```bash
   make


2. Написать программу, например hello.fox:

   * Моя первая программа на Fox
   local name = "World"
   print "Hello, " + name

   func add(number a, number b)
       return a + b
   endfunc

   print add(2, 3)

   local nums = [10, 20, 30]
   print count(nums)

   for i = 1 to 3
       print i * i
   endfor

   if count(nums) == 3 and not false
       print "все работает"
   endif

3. Скомпилировать и запустить:

   ./foxc hello.fox     # создаст hello.c и нативный бинарник hello_app
   ./hello_app

4. Ожидаемый вывод:

   Hello, World
   5
   3
   1
   4
   9
   все работает

   Компилятор сам вызывает системный gcc; флаг -lm подключается
   автоматически. Готовые примеры лежат в examples/
   (test.fox, functions.fox, types2.fox, arrays.fox).

### Windows (без WSL и без пакетных менеджеров)

Fox компилируется в C, поэтому на машине нужен любой C-компилятор. Под Windows есть три
нативных пути, от самого простого к «уже всё стоит»:

**Путь 1 — w64devkit (рекомендуется).** Портативный архив с gcc и make, без установщика:
1. Скачай zip со страницы релизов github.com/skeeto/w64devkit.
2. Распакуй, например, в `C:\w64devkit`.
3. Добавь `C:\w64devkit\bin` в PATH (Параметры системы → Переменные среды).
4. В новом окне cmd: `build.bat` (или `make`), затем `foxc examples\hello.fox` и
   `examples\hello_app.exe` — всё как на Linux.

**Путь 2 — MinGW одной командой.** Если winget/Chocolatey не страшны:
`winget install -e --id BrechtSanders.WinLibs.POSIX.UCRT` или `choco install mingw`.
Дальше те же команды, что на Linux.

**Путь 3 — уже стоит Visual Studio / Build Tools.** Ничего не ставим:
`build.bat` сам соберёт foxc через `cl`. Чтобы и программы .fox собирались через MSVC,
задай один раз шаблон команды компилятора:

```bat
set FOXC_CC=cl /nologo {src} /Fe{out}

foxc подставит вместо {src} сгенерированный .c и вместо {out} имя бинарника
и вызовет эту команду вместо gcc по умолчанию. Бинарники под Windows получают
имя имя_app.exe.

Управление

    print "много"

    print "средне"

    print "мало"

do case
    case x == 1
        print "один"

        print "другое"

for i = 1 to 10

Функции

func greet(string name)
    return "Hello, " + name
endfunc

func banner()
    print "---"
endfunc

print greet("Fox")   * выражение
banner()             * оператор


Правила: функция объявляется до первого вызова; рекурсии нет;
типы параметров обязательны; тип возврата выводится из return;
имена встроенных функций зарезервированы.

Встроенные функции

Вызов,                      Результат

len(s)                      длина строки
upper(s) / lower(s)         регистр
trim(s)                     пробельные символы по краям долой
substr(s, start, count)     подстрока; start с 1 (как в VFP)
str(n)                      число → строка
val(s)                      строка → число
count(list)                 длина списка

Списки (текущие возможности)

local a = [1, 2, 3]
local b = a          * глубокая копия, не алиас
print count(a)       * 3
a = [9]              * перезапись целиком
print count(b)       * по-прежнему 3


Индексация, append и for each появятся в следующих шагах roadmap.

Ограничения и особенности (честно)

    Числа — всегда double: целые точны до 2^53; print печатает
    через %g (6 значащих цифр), поэтому 1234567 выведется как
    1.23457e+06.
    Память строк и списков не освобождается (GC не подключён).
    print списка и сравнение списков запрещены на уровне компилятора.
    Функции не принимают и не возвращают списки.
